# WS53 完整检查记录（2026-10-21）

测试硬件：更换后的 WS53 A 板，J-Link OB-RA4M2-Full，100 kHz SWD。
使用本分支实际源码、锁定的 Jim Tcl/libjaylink 子模块独立构建的 Linux x64 二进制。
不是用 hs-openocd 的二进制替代验证。未擦写 Flash；借用的 ITCM/DTCM 内容先备份再恢复，恢复比对通过。

## 通过

- 8/16/32 位 RAM 交叉读写及非对齐字节操作；全部保存寄存器保持不变。
- GPR、FPR、CSR 写入/读回/恢复。
- ITCM 确定性指令单步；硬件断点命中、保留断点跨越、移除。
- 写、读、读写观察点分别实际命中并移除。
- 8 个触发器占满，第 9 个申请正确失败，随后释放成功。
- ITCM 软件断点命中、跨越、重新安装和原指令恢复。
- ITCM/DTCM/寄存器恢复后应用继续运行。
- SDK GDB attach、PC/SP/RA、指令字节读取、stepi、detach、再次 attach/detach，退出码 0。
  未加载匹配 ELF，因此不宣称已验证源码级断点。
- `reset halt` 在 `0x10000` 停止，单步到 `0x10004`。
- 先安装 `0x10080` 硬件断点，再 `reset run`，断点在复位后重新安装并实际命中。
- 六项源码配置回归、九项 ELF 工具测试通过；24,512 条短内存指令编码与 WS63 SDK objdump 一致。
- Linux x64 构建和 `git diff --check` 通过。原有驱动仍有编译警告，构建选项见 ws53.md。

## 复位修复回归

复位根因：`NDMRESET` 保留 PLL 时钟选择，ROM `0x11ADC` 关闭 PLL 后 CPU/AP1 停钟。
单步确认触发点；先切换 MCU 到 XO 的对照实验可以完成启动。
实现检查非活动通道、配置 XO、切换 normal/sleep mux 并验证通道状态；失败不继续运行。

- 两次连续 `reset halt` 分别切换到两路 MCU 通道，均读回无分频 XO；入口单步通过。
- 复位前设置的 ROM 硬件断点在复位后重新安装并命中。
- 不设置启动断点的 `reset run` 后等待 5 秒，再暂停、读指令、单步和继续。
- 从暂停和运行状态分别执行复位，连续 3 轮上述启动检查通过。
- 重复复位后的 SDK GDB attach、stepi、detach、再次 attach/detach 退出码 0。
- 完整 RAM/寄存器/软硬件断点/观察点检查在修复后的二进制上重跑通过。

复位回归脚本：`contrib/ws53/check_reset.py`。脚本遇到命令错误或断言失败返回非零，
结果 JSON 的 `passed` 也为 false，不将失败记录当作测试成功。复位检查会丢弃应用运行状态。

启动窗口仍观察到短暂 SWD 奇偶校验错误/重新连接，之后自动恢复并完成上述检查；
本次修复的是可确定复现的持续 WAIT，不宣称启动全过程没有传输错误。
