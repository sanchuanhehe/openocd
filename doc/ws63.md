# WS63 功能参考

> 来源：以下 WS63 功能与硬件验证记录引自 [PR #22](https://gitcode.com/HiSpark/hs-openocd/pull/22)。本次移植仅完成其自动化测试，未重新进行 WS63 板卡或 Flash/RTOS 实测。

本适配将上游 fork 中的 WS63 功能移植到海思 OpenOCD 0.12.0-1.0.0.5 的 `riscvcs` 后端。
通过 `target/ws63.cfg` 中的 `riscv ws63 on` 显式启用。
普通 RISC-V 和其他 `riscvcs` 芯片保留原路径。操作步骤见[使用指南](ws63-setup.md)。

## 接口与范围

| 功能 | 实现 |
|---|---|
| AP0 调试 | 保留海思 CoreSight DMI 传输；暂停、继续、GPR/FPR/CSR、单步 |
| RAM | CPU program buffer 访问，检查每次传输结果，保存并恢复临时寄存器 |
| AP1 | ROM、Flash、MMIO 使用系统总线；独立 `WS63.ap1` 目标支持原始访问 |
| 断点 | RAM 软件断点；ROM 和默认 Flash 断点转换为硬件；支持跨断点单步和重插 |
| 观察点 | 读、写、读写，范围拆分和非对齐范围；标量访存解码识别边界误触发 |
| 复位 | 软件断点转硬件，恢复签名镜像；重装触发器；全复位后使调试程序缓存失效 |
| NOR Flash | GD25Q32 4 MiB，4 KiB 擦除，编程和 SPI 读回校验，状态保护恢复 |
| LiteOS | 显式启用 `liteos_ws63`，任务名/状态/优先级，已保存寄存器和回溯 |
| ELF | `prepare_elf.py` 为支持的 WS63 栈操作合成 CFI，保留可加载节 |

## 内存与缓存

CPU D-cache 是 write-back。原始 AP1 RAM 读取可能落后于 CPU 视图。
先暂停 CPU，再执行 `ws63_ap1_sync_dcache` 后转储。
通过 AP1 修改代码后执行 `ws63_sync_code`。
CPU 目标禁止普通内存写入 BootROM 和 NOR Flash；Flash 必须使用驱动命令。

海思现有 `batchcs` 快速通道没有逐次传播 AP 操作失败。
WS63 的 RAM 路径使用有检查的同步 program buffer 操作，不修改其他芯片的批量路径。
该取舍优先保证寄存器恢复和错误报告，RAM 吞吐量与现代上游后端不同。

## Flash 与断点

`WS63_FLASH=0` 禁用 Flash bank。默认启用 Flash bank，但不启用 Flash 软件断点。
在加载目标配置前设置 `WS63_FLASH_SWBP=1` 才允许软件断点擦写 Flash 扇区。
先进入完成启动校验的应用，再安装这类断点。

每次擦除或编程前，驱动在 `WS63_FLASH_BACKUP_DIR` 写入独立的原始备份。
备份失败就停止操作。驱动不理解签名包、分区表或升级事务，也不自动回滚。
普通编程后必须复位；失败会阻止当前会话继续或复位，恢复并核对数据后重启调试会话。

安装的软件断点与普通内存写入、Flash 擦写范围相交时，拒绝操作。
删除断点时若指令已被外部覆盖，保留新字节并告警。
独立 `WS63.ap1` 是原始总线访问，会绕过 CPU 目标的写入保护。

复位前为每个软件断点预留硬件槽位，再恢复原指令并转换断点类型。
槽位不足时拒绝复位；已完成的转换保持有效。
硬件断点和观察点共用 8 个槽位，范围拆分可能占用多个槽位。

观察点识别自然对齐的 RV32 标量访存、压缩访存和 WS63 短访存指令。
遇到未知或多寄存器访存时保持暂停，不自动跳过。

## LiteOS 上下文

适配布局为 RV32F `LosTaskCB=96`、`TaskContext=272`；在原 BearPi SDK v1.0.102
和本次 1.10.108 示例中检查该布局。其他 SDK 必须重新用配套 ELF 检查。
运行时不会自动证明 ELF 与 Flash 匹配，不启用 `-rtos auto` 探测。

非当前任务是只读的保存上下文。未可靠保存的寄存器显示 `<unavailable>`，
寄存器写入和单步被拒绝；切回当前任务后操作。
`thread` 不切换芯片的实际运行任务，不实现 scheduler-locking。
无符号 ROM、异常入口或未识别栈操作仍可能中断回溯。

## 与海思现有改动的关系

移植基线是海思提交 `d64eb62fff03c393d3dacc1c86507ebf96b0c81f`。
它保留海思的 AP0、3322 ungate、CMSIS-DAP 和 J-Link 驱动，未整体替换新版上游 RISC-V 文件。
现有开放 PR !21 为通用 `riscvcs` 加入 MEM-AP 内存访问选择；本适配独立完成
WS63 的地址分类与缓存语义，没有直接依赖尚未合并的 PR。
后续合并 !21 时，应保留 WS63 RAM 的 CPU 一致性路径。

开发验证使用 Linux、CMSIS-DAP v2、J-Link OB 和 SDK 1.10.108 的 GPIO2 示例。
Flash 操作中断后，保持板卡供电和 CPU 暂停，恢复并校验扇区及保护位后再复位或运行。
Flash 写入依赖 POSIX 的持久备份；Windows 构建保留调试/读出，在修改 Flash 前返回不支持，
不把没有目录持久化保证的备份当作成功。
上述两种探针的结果不代表其他探针、其他芯片或其他宿主平台已通过实测。
WS63 显式采用 `ndmreset`，不使用 `HISPARK_TRACE_MODIFIES` 的跳转 PC 复位逻辑；
仍需单独验证 trace 版本和各发布平台。
